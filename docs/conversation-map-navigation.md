# Message navigation for Workbench Topic map

Public bindings expose `focusMessage({ conversationId, threadId, messageId })`, returning `{ success: true, status: 'opened' }` or a failure code (`not_ready`, `stale_context`, `message_unavailable`, `message_load_failed`, `message_focus_timeout`). The host must resolve authorization and activate the exact thread before requesting message focus. This method does not grant access, navigate to another user scope, send a message or stop a run.

Workbench `assistant.conversation` requests may include `messageId` and `preserveView`. Navigation first waits for host authorization, switches the persisted thread, then waits for focus completion. Old requests and execution anchors remain compatible. The focus hook uses existing paginated history, retries pages only when progress is made, highlights the matching persisted message element, and cancels stale work on unmount/API-organization changes or a superseding branch navigation.
